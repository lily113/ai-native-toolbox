# 云函数部署清单

> 目标：把这几个云函数放到**你自己的云环境**里。云端跑不起来时，小程序里会看到
> `no baseresponse` / `FunctionName not found` 这类英文报错 —— 十有八九是这份清单里某一步没做。

## 0. 前置（只做一次）

- 小程序 `app.js` 里的 `ENV` 必须是你的云环境 ID：当前是 `cloud1-d3gxrubwgdf9f71c7`
- `project.config.json` 里要有 `"cloudfunctionRoot": "cloudfunctions/"`（已经有了）
- **开发者工具里的「云开发」环境要绑定到项目**：
  点工具栏左侧 **「云开发」** 按钮，打开一次控制台（这一步会把项目和环境绑上），然后关掉

## 1. 给云函数根目录选环境（最容易漏的一步）

> 报错原文：`请在编辑器云函数根目录（cloudfunctionRoot）选择一个云环境`

1. 开发者工具左侧文件树 → **右键 `cloudfunctions` 这个目录**（不是某个具体函数）
2. 菜单里选 **「选择云环境」** → 选 `cloud1-d3gxrubwgdf9f71c7`
3. 选完后再去部署单个函数（下面第 2 步）

如果右键菜单里**没有**「选择云环境」：说明项目还没绑上云环境 → 先做第 0 步里的「打开一次云开发控制台」。

## 2. 部署每个函数

对 `cloudfunctions/` 下的每个函数目录（`login`、`deepseek`、`remind`、`friend`）：

1. **右键该函数目录**
2. 选 **「上传并部署：云端安装依赖」**
   - ⚠️ 一定选**带"安装依赖"**的那一项。选「上传所有文件」不会装 `wx-server-sdk`，
     函数一启动就崩，小程序里表现为 `no baseresponse`
3. 等 1~2 分钟；到 **云开发控制台 → 云函数** 看到状态正常即可

## 3. 集合（数据库）

| 集合 | 谁用 | 说明 |
| --- | --- | --- |
| `planner_data` | 云端同步 | 文档 `_id` = openid，存你这份数据（分块上传） |
| `planner_history` | 云端同步 | 最多 5 个历史快照，可回滚 |
| `planner_team` | 同门小队 | 小队 + 成员，邀请码在这里 |
| `planner_team_stat` | 同门小队 | 每人每周的**汇总数字**（天数/时长/冰课数），不含任何笔记 |

- 第一次调用会自动创建（云函数里用 `db.createCollection` 兜底）
- 权限保持默认 **「仅创建者可读写」** 就行 —— 小程序端**不直接读数据库**，
  全部走云函数（服务端有全权限）

## 4. 环境变量

| 函数 | 变量 | 用途 |
| --- | --- | --- |
| `deepseek` / `login` | `OWNER_OPENID` | 只有它能用 AI 教练（非本人直接拒绝，不产生费用） |
| `deepseek` | `DEEPSEEK_KEY` | DeepSeek 的 API Key |
| `remind` | `EXAM_TMPL_ID` | 考级提醒的订阅消息模板 ID；不填就不发提醒 |

## 5. 定时触发器（只有 `remind`）

`cloudfunctions/remind/config.json` 里已经写了 `0 0 9 * * * *`（每天 9:00）。
部署后在 **云开发控制台 → 云函数 → remind → 定时触发器** 里确认它出现了。

## 常见报错对照

| 报错 | 真实原因 | 怎么办 |
| --- | --- | --- |
| `请在编辑器云函数根目录（cloudfunctionRoot）选择一个云环境` | 云函数根目录没绑环境 | 第 1 步 |
| `no baseresponse` | 函数不存在 / 部署时没装依赖 | 第 2 步（选「云端安装依赖」） |
| `FunctionName not found` / `-501000` | 函数还没部署 | 第 2 步 |
| `permission denied` / 集合不存在 | 数据库集合没建 / 权限不对 | 第 3 步 |
| 超时 | 冷启动慢（尤其刚部署完） | 过十几秒再试 |
