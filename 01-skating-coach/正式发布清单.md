# 正式发布清单（对外公开上架）

> 目标：把现在这个体验版变成**所有人可搜可用**的正式版。
> 用法：从上往下打勾。第一步最耗时（备案），建议今天就提交。

## 一、平台侧三件前置（必须做，缺一件就发不出去）

### 1. 小程序备案（ICP）——最耗时，先做

微信公众平台 → 设置 → 基本设置 → **小程序备案**。个人主体也能备案。

- 需要：主体信息（身份证）、负责人手机号与人脸核验、小程序简介
- 时长：一般几天到两三周（取决于是不是被退回补材料）
- **没备案不能提交发布**，所以它决定了整体时间线

### 2. 服务类目

微信公众平台 → 设置 → 基本设置 → **服务类目**。

- 选与"个人训练记录工具"匹配的类目（工具/效率方向）
- 个人主体可选类目有限，**以你后台看到的可选项为准**；类目不匹配会被直接拒审
- 不要选需要资质的教育/医疗/金融等类目

### 3. 用户隐私保护指引

微信公众平台 → 设置 → **服务内容声明 → 用户隐私保护指引**。

这个小程序实际用到的东西，照着声明：

| 收集的信息 | 用途 | 说明 |
|---|---|---|
| 微信 openid（用户标识） | 区分用户、同步数据 | 通过云函数 `login` 获取 |
| 用户填写的训练记录、笔记、动作库 | 记录与多设备同步 | 存在用户自己的云开发空间里 |
| 相册**写入**权限 | 保存分享图到相册 | 只写入，不读取相册 |

**没有**用到：位置、通讯录、麦克风、摄像头、相册读取、手机号。

> ⚠️ 没声明就上架的直接后果不是"审核不通过"，而是真机上这两个功能**直接失败**：
> 「数据备份 → 导入文件」（`wx.chooseMessageFile`）和分享图「保存到相册」（`wx.saveImageToPhotosAlbum`）。

### 4. 云开发环境

- 确认环境未欠费、未过期（公众平台/云开发控制台能看到）
- 不需要配置服务器域名（全部走云开发）

## 三、上传与自测

1. 开发者工具 **Cmd+Q 重启**（否则会报 `ENOENT ...tmp_test_pages.js`）
2. 本地先跑一遍：`cd figure-skating-mp && python3 ../tools/audit_mp.py`，再依次跑 `tools/mp_tests/` 下 9 个测试（都过才上传）
3. 开发者工具「上传」→ 版本号填 `2026.10.08.31`（或你实际上传的那个），备注写清这次改了什么
4. 公众平台 → 版本管理 → 把这一版**选为体验版** → 自己手机上完整走一遍：
   - [ ] 记一条训练（含勾动作、写笔记）→ 保存 → 首页出现
   - [ ] 动作库：改个名、"最久没练"排序、标记「已掌握」
   - [ ] 考级：关注一级、填考级日期、看倒计时、复制考前清单
   - [ ] 回顾：生成月度报告图 → 存相册
   - [ ] 记录详情：生成分享卡 → 存相册
   - [ ] 设置：数据在哪（本机=云端）、导出文件、从云端恢复
   - [ ] 换一台手机（或让朋友）打开，确认数据跟着微信号回来

## 四、提交审核

版本管理 → 提交审核。**审核说明**可以直接用下面这段：

> 这是一个个人使用的花样滑冰训练记录工具：记录每次训练的时间、动作、笔记，查看月度统计，对照国家等级测试大纲的结构做备考计划。
>
> 数据说明：用户数据保存在其**本人**的微信云开发空间（每个用户一份，只有本人可读写），不对外共享；不收集位置、通讯录、相册读取等敏感信息（仅申请相册**写入**权限用于保存用户自己生成的分享图）。
>
> 关于内置内容：等级测试相关信息只包含**级别结构与时长、动作名称等事实性信息**，不含教材正文、图片或扫码内容。

**常见被拒原因与改法**

| 被拒理由 | 怎么改 |
|---|---|
| 功能不完整/页面有占位内容 | 检查有没有没配好的入口（这次已经隐藏了订阅消息入口） |
| 类目不符 | 回到「服务类目」换一个与工具类匹配的 |
| 隐私指引与实际不符 | 补齐声明（见第一节第 3 条） |
| 涉嫌未备案 | 等备案通过再提审 |

## 六、发布之后要改怎么办

```
改代码 → 跑 9 个套件+审查 → 上传（版本号+备注）→ 选体验版自测
→ 提交审核 → 通过后发布
```

- 用户重新打开小程序就会自动更新，不需要他们操作
- **建议一直保持"先体验版自测，再提交审核"的习惯**

**数据不会因为更新丢**（现有机制）：
- 升级前自动备份 + 升级后自检（少记录/少文字会提示，可一键回滚）
- 云端 5 个历史版本
- 合并只做并集（只补不删）

**唯一纪律**：数据结构**只加字段、不删字段、不改字段含义**；要改就写迁移（像 `normalizeRecord` 那样读的时候补默认值）。目前所有字段都是这么处理的（`coach`、`status` 这些新字段都显式进了白名单）。

## 七、万一线上出问题

按顺序试，每一层都能独立生效：

1. **版本回退**：公众平台 → 版本管理 → 版本回退（回到上一个已发布版本，秒级生效）
2. **用户数据回滚**：云端 `planner_history` 有 5 个快照，用户可在「设置 → 找回云端历史版本」自助恢复
3. **本机回滚**：设置 → 高级 → 「恢复导入前」/「恢复升级前数据」

> 发布后的第一周，建议每天看一眼云开发控制台的调用量和错误日志（公众平台也有运维中心）。
