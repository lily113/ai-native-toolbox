# 发布前检查清单（小程序）

> 唯一硬要求：**用户原来的数据一个字都不能丢**。
> 每次发版都按这个走一遍；凡是"改数据"的代码，默认按最保守的方式写。

## 一、写迁移代码时的三条规矩

1. **只加不删**：迁移只能"补字段 / 补条目 / 合并内容"，不能 `filter` 掉用户数据、不能整条覆盖。
   要清理旧结构，先把内容搬到新地方再丢外壳（参考 `harvestExamSections`）。
2. **可重复执行（幂等）**：迁移跑两遍结果必须一模一样。启动时会跑，导入、云端拉取后也会跑，
   "只跑一次"的假设迟早会被打破（`migrateMergeNotes` 就是这么从一次性改成可重复的）。
3. **旧字段要接手，不能让它变成隐形数据**：小程序看不到的字段（历史遗留的 `notes` /
   `lessonSummary` 等），必须在打开编辑、导入、拉取这些入口上并进 `content`，
   否则编辑器保存时会把它清空 = 真丢字。

## 二、发版前必做

- [ ] **版本号 +1**：`figure-skating-mp/utils/const.js` 里的 `APP_VERSION`（升级保护靠它触发）
- [ ] **真实数据演练**：导出最新数据 → `tools/mp_tests/fixtures/real-export.json` → `node tools/mp_tests/realdata.test.js`
      （至少要看到「每一行文字都还在」「一键恢复后每一行文字都回来了」）
- [ ] **升级演练**：`node tools/mp_tests/upgrade.test.js`（含坏迁移演练 + 幂等性）
- [ ] **页面逻辑自测**：`node tools/mp_tests/cats.test.js`、`node tools/mp_tests/pages.test.js`
- [ ] **静态自检**：`cd figure-skating-mp && python3 ../tools/audit_mp.py`（8 项，必须 0 问题）
- [ ] **开发者工具里自己点一遍**：改动的页面 + 打开一条老记录保存 + 首页/回顾页数字对得上
- [ ] **自己先导出一份备份**（设置 → 数据备份 → 导出为文件），存到微信收藏/文件传输助手

## 三、发布后第一次打开要对照

- [ ] 设置 → 高级 → **升级自检**：显示"通过"（右侧灰色提示条里）
- [ ] 设置 → 数据概览：**总记录数 / 累计节数 / 基线**和发布前一致；**云端体积**没超 900KB
- [ ] 随手打开一条老记录看文字在不在；改一下再保存，文字不少
- [ ] 首页日历双色点、回顾页统计正常

数字不对：**先别再上传云端**，用「设置 → 高级 → 恢复升级前数据」或数据备份恢复。

## 四、升级保护是怎么工作的（`utils/store.js`）

- 启动时发现 `meta.appVersion` 和 `APP_VERSION` 不一致 → 判定为"换版本了"：
  1. 把整份数据（记录/动作/分类/考级/里程碑/模板/meta）**存一份本机快照**（只留最近 1 份；
     太大就不存并在自检里标注，此时靠云端 5 份历史快照兜底）
  2. 把"用户写下的每一行字"记成指纹
  3. 跑完迁移再比对：记录条数不能变少、每一行字都必须还能找到
- 不通过 → 首页弹一次提醒，`设置 → 高级` 里显示红色警告，并且可以**一键恢复**：
  恢复是"只补不删 + 笔记取并集"——补回被删的记录，把被吞掉的文字并回原记录，
  同时不会抹掉升级之后新写的内容。
- 同一版本日常启动不做这些事，没有任何额外开销。

## 五、还有哪些已知边界（不是这次能修好的，知道就行）

- **云文档 1MB 上限**：现在约 80KB。数据概览里能看到体积，接近 900KB 就该清理或导出备份了。
- **同名同分类的重复动作**：`dedupeMoves` 会保留一个、丢掉重复的（连带它的组合）。
  记录里的文字不会丢，但那条动作在首页卡片上不显示。动作库别出现重名动作。
- **本机存储**：微信单键上限 1MB、总量 10MB。快照只留 1 份就是为此。
- **开发者工具与手机是不同 openid**，且开发者工具默认不自动同步（防止测试数据推到云端）。
