# 04 · 把求职流程自动化掉的工作流

> 一个人 + 一排 agent。
> 这个项目解决的问题不是"怎么让 AI 干活"，而是**"怎么让它每次都按同一个标准干活"**。

---

## 起点：一个每周都在重复的痛点

我在找工作，每周要看很多 JD。手工比对"这份工作和我匹不匹配"极其耗时，而且更糟的是——**同一份 JD 今天看和明天看，结论可能不一样。**

判断口径会漂移。这才是真问题。

---

## 做法：用"文档契约"代替"更长的提示词"

我最后没有去堆更复杂的 prompt，而是把**判断口径、输出格式、目录约定**全部写进一份 `CLAUDE.md`——相当于给 AI 一份可复用的工作说明书。

```
.claude/CLAUDE.md          # 工作说明书：判断口径 + 输出格式 + 行为约定
JDs/                       # JD 原文自动归档（公司_岗位_年份.md）
resume/
├── 01_战略方向/            # 按方向分层的简历库
├── 02_投资方向/
├── 03_数据AI方向/
└── ...
applications/投递记录.xlsx  # 带颜色编码的状态跟踪
interview-prep/            # 进入面试自动生成 briefing
```

### 三个关键设计

**① 固定的输出格式**

分析任何一份 JD，都强制输出三段：

```
【必须满足】    ← 硬性门槛
【加分项】      ← 差异化空间
【我的匹配度评估】 ← 结论必须落到"投不投"
```

**格式约束的价值不在于好看，在于它逼着判断落地。**没有第三段，AI 很容易给你一堆"这个岗位要求数据分析能力"式的废话。

**② 原文先归档，再分析**

收到 JD 原文的第一步永远是**存盘**，而不是分析。这样每一条判断都可追溯——三个月后回头看"我当时为什么判断不匹配"，有原始材料可查。

**③ 简历库的版本纪律**

每个方向的底本 + 针对具体岗位的定制版分层存放，命名规范固定，并且**每次定制后判断"这次的改进是否有通用价值，有就回灌到底本"**。

这条规则解决的是一个很隐蔽的问题：**定制简历做多了，好的表达会散落在各个版本里，底本永远是旧的。**

---

## 为什么这件事和「AI 原生组织」有关

这本质上是一个**微型的 AI 原生组织实验**：

| 传统组织 | 这个工作流 |
|---|---|
| 用岗位说明书和流程定义协作 | 用 `CLAUDE.md` 定义协作 |
| 新人要培训才能按标准做事 | agent 读一遍文件就按标准做事 |
| 标准在执行中逐渐走样 | 标准写在文件里，每次都一样 |
| 知识散在个人脑子里 | 知识沉淀在目录结构里 |

**一个人带着一排 agent，能做过去一个团队才做得成的事**——这句话我在这套工作流里有很具体的体会。

---

## 我从中得到的最重要的一条体会

> **让 agent 干活不难，难的是让它每次都按同一个标准干。**

所以我后来意识到，写更长的提示词是错的方向，**写清楚契约才是**。判断标准要变成可检查的规则（"必须输出三段"、"原文先归档"、"定制后回灌"），而不是留在脑子里的感觉。

我怀疑这条体会在真实的组织里同样成立——**AI 原生组织的关键可能不是模型能力，而是组织能不能把自己的判断标准写成机器可读的契约。**
